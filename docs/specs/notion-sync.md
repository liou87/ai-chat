# Spec：笔记库接入 Notion（只读导入）+ 笔记分块检索

状态：已实施（分块改造、Notion 同步、前端入口均已完成并验证）
关联需求：笔记模块能检索到 Notion 里已有的内容，本地仍是唯一的写入入口；长笔记要能被完整检索到，不能只检索到开头
依赖：docs/specs/postgres-pgvector-migration.md，数据库迁移已经完成

## 1. 背景与目标

用户在 Notion 里已经有笔记习惯，希望这些内容也能被 agent 的语义检索找到，不用把东西重新抄一遍进这个项目。目标是把指定 Notion 数据库里的页面拉进本地 notes 表，检索的时候本地笔记和 Notion 笔记一视同仁。

Notion 页面经常很长，而现在用的 embedding 模型（bge-small-zh）只能处理约 512 个 token，超出部分会被截断，一页一个向量的话只有开头能被检索到。所以这次同时把检索改成分块：一条笔记切成多个片段，每个片段一个向量，所有笔记（本地的和 Notion 的）统一走这一套。

不做双向：本地新建、编辑的笔记不会推回 Notion；Notion 那边新增、编辑的内容需要手动触发一次同步才会体现到本地。

## 2. 范围

这次做的事：笔记分块检索，notes 表的向量搬到新的 note_chunks 表，检索改成按分块查再按笔记去重；从一个指定的 Notion 数据库拉取页面，导入或更新到 notes 表；页面正文里的文字类内容会被抓取，包括段落、标题、列表、引用、待办、代码块、表格，以及折叠块和缩进子项里嵌套的内容（最多递归 3 层），图片和子页面（child_page）暂不处理；增量同步，Notion 页面没改过就跳过，不重复算 embedding；触发方式是手动的，聊天里让 agent 同步，或者笔记面板里点一个按钮；Notion 来源的笔记在本地不允许删除，界面上标出哪些笔记来自 Notion。

这次不做的事：Notion 到本地的删除同步，Notion 页面删了本地对应笔记不会自动跟着删；本地到 Notion 的任何写入；定时自动同步，不做轮询也不做 webhook；多个 Notion 数据库或页面源，先只支持一个。

## 3. 前置条件

以下是用户需要自己完成的部分，不是代码里能自动化的：去 notion.so/my-integrations 建一个内部集成，Capabilities 里只勾 Read content，拿到 secret token；建一个全页数据库放笔记，保留默认的标题属性，正文写在每一页里面，测试用的页面里要有一页写得比较长，用来验证分块；在数据库页面右上角三个点菜单的 Connections 里授权给这个集成，没授权的内容 API 读不到，这是 Notion 的权限模型；拿到数据库的 ID，也就是数据库页面网址里问号前面那 32 位。

对应的环境变量：

| 变量 | 说明 |
|---|---|
| NOTION_API_KEY | 集成的 secret token |
| NOTION_DATABASE_ID | 要同步的数据库 ID |

## 4. 数据模型

notes 表去掉 embedding 列，原来在它上面的 HNSW 索引一起去掉。source、external_id、external_updated_at 三个字段已经在数据库迁移时建好，这次不用动：source 是 local 或 notion，external_id 是 Notion 页面 id，external_updated_at 是 Notion 页面的 last_edited_time，原样存 UTC，不转本地时区。

新增 note_chunks 表：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 整数，主键 | |
| note_id | 整数，外键指向 notes.id，建索引 | 删除笔记时级联删除它的分块，不用自己写清理代码 |
| chunk_index | 整数 | 这是第几个分块，从 0 开始 |
| content | 文本 | 分块的原始文本，不含标题 |
| embedding | 512 维向量 | 对标题加分块文本算出来的向量，建 HNSW 索引，用余弦距离 |

这是一次新的 Alembic 迁移：建 note_chunks 表和两个索引，删掉 notes.embedding 和它的 HNSW 索引。当前数据库是空的，不需要把旧数据补算成分块。提醒一下，autogenerate 生成的迁移文件涉及向量列时会漏掉 import pgvector.sqlalchemy，生成后要手动补上。

## 5. 分块规则

分块逻辑写成一个纯函数放在 services/chunking.py，输入笔记正文，输出分块文本列表，不依赖数据库，方便单独测试。

规则是这样：先按换行把正文拆成段落，去掉空行；然后按顺序把段落合并成分块，一个分块累计到不超过约 400 字就继续往里加，加下一段会超过就另起一个分块；遇到标题行（以一到六个井号加空格开头）也另起一个分块，这样不同小节不会被合并到一起，连续的标题（大标题紧跟小标题）合在一起，不单独成块；如果单个段落本身就超过 400 字，对这个段落按 400 字一段硬切，相邻两段重叠 50 字，避免句子被切断后前后都丢了上下文。段落合并出来的分块之间不做重叠，因为段落边界本身就是语义边界。400 字这个数是给模型 512 token 的上限留了余量。正文为空的笔记，用标题当作唯一的分块。

按标题切分是验证第一步时发现的：一个分块里如果混了两个话题，其中一个话题的相似度会被稀释，在小模型上会低到被无关短笔记的噪声盖过。一页 Notion 里常常有好几个小节，所以把标题当作强制的分块边界。已知的小副作用是代码块里以井号开头的注释行也会被当成标题，只会让分块稍微碎一点，不影响正确性。

算向量时，每个分块的输入是标题加换行加分块文本，这样长笔记后半段的分块，即使自己没有出现主题词，也能和主题保持关联。分块的 content 字段存的是不含标题的原始文本。一条笔记的多个分块用批量方式一次送进 embedding 模型，不是一块调用一次。

## 6. 检索

search_notes 的对外行为不变，还是返回笔记列表，每条带一个相似度分数，前端不用改。内部改成：先在 note_chunks 上用 HNSW 索引按余弦距离取最近的 top_k 乘 4 个分块，通过 note_id 关联 notes 表拿笔记信息和按分类过滤；然后在 Python 里按笔记去重，每条笔记只保留它得分最高的那个分块，分数还是用 1 减去距离；最后取前 top_k 条笔记返回。

多取 4 倍分块再去重，是因为一条长笔记可能有好几个分块都排在前面，直接取 top_k 个分块的话，会被同一条笔记占满。另外要知道一个限制：按分类过滤发生在近似最近邻查找之后，所以过滤后结果可能少于要求的数量，多取 4 倍也能缓解这一点，个人规模下问题不大。

## 7. Notion API 调用流程

用 httpx 直连 REST API，跟 services/websearch.py 一个写法，不引入 notion-client 这个官方 SDK，固定带 Notion-Version: 2025-09-03 请求头（Notion 今年把数据库查询迁移到了新的 data_sources 端点，用旧的按 database id 查询的接口会走废弃路径）。

第一步，拿 data_source_id：请求 GET /v1/databases/{数据库 ID}，响应里 data_sources 数组第一项的 id 就是。这一步结果在同步开始时缓存在内存里，一次同步只需要查一次。

第二步，分页拉页面列表：请求 POST /v1/data_sources/{data_source_id}/query，body 带 page_size 和 start_cursor（第一页不传 cursor），响应里的 results 是页面对象数组，还有 has_more 和 next_cursor 用于翻页。每个页面对象里，id 是页面 id，last_edited_time 是最后编辑时间，properties 里要找 type 为 title 的那个属性取标题文本。按类型找而不是按属性名字找，因为默认叫 Name 的这个属性经常被用户改名，但类型为 title 的属性在每个数据库里有且只有一个，这个规则是 Notion 自己保证的。

第三步，拉每个页面的正文：请求 GET /v1/blocks/{页面 id}/children，同样要分页。凡是带 rich_text 数组的文字类 block 统一处理，包括段落、一二三级标题、无序列表项、有序列表项、引用、待办事项、代码块，以及折叠块和标注块这类同样带文字的块；取里面每一项的纯文本拼起来，各个 block 之间用换行分隔，代码块保留内部的换行原样存。一二三级标题在文本前加对应数量的井号和空格（比如二级标题存成"## 小节名"），分块时靠这个标记切开小节。

表格需要单独处理：表格 block 本身没有文字，要再请求一次它的 children 拿到每一行，每一行的单元格文字用" | "连成一行。

嵌套内容递归读取：如果一个 block 有子内容（比如折叠块里面的内容、缩进的子列表项），就继续请求它的 children，处理方式和外层一样，子内容的文字接在父块文字后面。最多递归 3 层，防止结构很深时请求数失控。图片、子页面（child_page）、子数据库这类没有正文文字的块直接跳过，不报错，也不进入。子页面的内容不会被同步，想同步的话需要把它移进这个数据库里作为一行。

用你的真实数据库读过一遍：标题属性叫"名称"（印证了按类型找标题的做法）；一页有约 5300 字纯文本外加 8 个代码块和 4 个表格；一页只有图片没有文字；一页有 11 个折叠块和 2 个子页面。

请求都是逐个页面按顺序发，不并发，Notion 限流大约每秒 3 次，个人规模的页面数足够。

## 8. 同步算法

落在 services/notion.py 的 sync_notion_notes(db) 函数里：先拿一次 data_source_id；然后分页遍历所有页面，对每个页面，先按 external_id 查本地有没有对应记录。没有就拉正文，新建一条笔记（category 是 note，source 是 notion）并生成分块，计入新增；有的话比较 Notion 的 last_edited_time 和本地存的 external_updated_at，如果 Notion 那边更新过，就重新拉正文，更新笔记，删掉旧分块重新生成，计入更新；没更新过就跳过，计入跳过。每处理完一个页面就提交一次数据库，所以中途失败时已经成功的部分保留。翻完所有页之后，把本地 source 是 notion、但 external_id 不在这次页面列表里的笔记删掉，也就是 Notion 里删掉或者移出这个数据库的页面，计入删除；分块靠外键级联一起删。这一步只有页面列表完整读完才会执行，读取中途出错（比如 token 失效、网络断了）会直接返回错误，不会误删；拉正文失败的页面仍在列表里，也不会被删。最后返回一个汇总：新增、更新、跳过、失败、删除各多少条。

services/notes.py 里新增 upsert_note_from_external 函数，接收 external_id、title、content、external_updated_at，先按 external_id 查一遍，存在就更新，不存在就新建，两种情况都会重新生成分块。同步是同步阻塞的，请求会一直等到所有页面处理完，个人规模不引入后台任务。

## 9. 删除限制和来源标记

DELETE /api/notes/{id} 遇到 source 是 notion 的笔记，返回 403，提示"来自 Notion 的笔记请在 Notion 里删除"。这样做是因为这次是只读导入，本地不是这些内容的主人，而且本地删掉的话下次同步会因为找不到这个 external_id 又被导入回来。agent 本身没有删除笔记的工具，不受影响。

笔记的返回结构里增加 source 字段。前端笔记列表里，Notion 来源的笔记在标题旁边显示一个小的灰色描边 Notion 标记，并且不显示删除按钮，避免用户困惑为什么删不掉。笔记正文在列表里默认只显示前几行（卡片视图 3 行，全页视图 4 行），实际测量发现内容溢出才显示"展开"，短笔记不出现这个按钮，避免长笔记（比如 Notion 长页面）占满整个列表。

## 10. 其他对外接口

agent 工具方面，services/tools.py 新增 sync_notion_notes，不需要参数，返回同步结果的汇总，方便在聊天里说一句"同步一下 Notion 笔记"就能触发。REST 接口方面，routers/notes.py 新增 POST /api/notes/sync-notion，内部直接调用 sync_notion_notes。前端方面，笔记面板（卡片视图和全页视图）加一个"同步 Notion"按钮，点击后调用上面这个接口，完成后刷新列表，并显示这次新增、更新了多少条。

## 11. 错误处理

没配置 NOTION_API_KEY 或 NOTION_DATABASE_ID 的时候，sync_notion_notes 直接返回一个"未配置 Notion 集成"的错误提示，不抛异常，跟 web_search 处理缺 key 的方式一致。Notion API 请求失败，比如网络错误、权限不够、数据库 id 不对，捕获异常后返回具体的失败原因。单个页面拉正文失败的话，跳过这一页，计入失败数，不影响其它页面继续同步。递归读取会让请求数变多，如果遇到 429 限流，按响应头里的 Retry-After 等待后重试，最多重试 3 次。

## 12. 实施顺序

分三步，每一步做完先验证再进下一步，这样出问题时能分清是哪一步引入的。

第一步，分块改造：新增 Alembic 迁移，写 chunking 和批量 embedding，改 create_note 和 search_notes，删除笔记时靠外键级联清理分块。只用本地笔记验证，这一步不涉及 Notion。

第二步，Notion 同步：写 services/notion.py，加 upsert_note_from_external、工具、REST 接口、删除限制和 source 字段返回。这一步需要真实的 Notion token 和数据库才能联调。

第三步，前端：笔记列表加来源标记、隐藏 Notion 笔记的删除按钮、加同步按钮。

## 13. 验证计划

第一步的验证：建一条很长的笔记（超过 1000 字），确认生成了多个分块；搜索一个只出现在这条笔记后半段的词，确认能搜到，这是分块要解决的核心问题；建一条短笔记，确认只有一个分块；删掉长笔记，确认分块被级联删除；用 EXPLAIN ANALYZE 确认检索查询走的是 note_chunks 上的 HNSW 索引；再跑一遍现有的 agent 存笔记、搜笔记流程，确认没有回归。

第二步的验证直接用已经配好的真实数据库（三个页面）：跑一次同步，确认新增 3 条；只有图片的那页正文为空，应该用标题当唯一分块；约 5300 字的长页面应该切成多个分块，并且里面的代码块和表格内容都在；带折叠块的那页抓到的字数应该明显多于只抓第一层时的约 500 字，说明嵌套内容读到了，两个子页面被跳过而不是报错；改其中一个页面的内容，再跑一次同步，确认只有改过的那条被更新，其余的走跳过，可以在日志里确认没有重复调用 embedding 服务，被更新的笔记分块也被重建了；搜一个只在 Notion 长页面后半段出现的关键词，确认能搜到；对 Notion 来源的笔记调用删除接口，确认返回 403；不配置 NOTION_API_KEY 的情况下调用同步，确认返回明确的未配置提示，而不是服务器错误。

第三步的验证：浏览器里确认 Notion 来源的笔记有标记、没有删除按钮，同步按钮能触发同步并刷新列表，本地笔记不受影响。

## 14. 已确认的决策

所有笔记统一走分块表；按段落合并、每块约 400 字的分块策略，遇到标题强制另起分块；分块算向量时带上标题；搜索结果按笔记去重取最高分分块；Notion 来源的笔记本地不允许删除；界面上标出笔记来源；title 属性按类型查找；external_updated_at 存 UTC；触发方式手动，同步阻塞；代码块和表格一起抓取；嵌套内容递归抓取最多 3 层，子页面不递归；同步范围是一个数据库，现有页面通过移动（不是复制）放进这个数据库，保证页面 ID 不变、以后能持续同步；Notion 里已经不存在的页面，同步时把本地副本一起删掉。

Notion 侧的配置已经完成并用真实数据验证过：内部连接只授予读取内容权限，授权对象是数据库整页，令牌和数据库 ID 都已填进 .env。
